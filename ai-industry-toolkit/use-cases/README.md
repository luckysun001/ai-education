## 案例模板

投稿请按这四段写，缺一段就很难被别人复用：

- **背景**：要解决什么问题（谁、多久做一次、原来怎么做的）
- **方案**：用了哪些工具 / 提示词 / 流程（**提示词要贴原文**）
- **成效**：量化或定性结果（说清衡量方式，别只写"效率提升"）
- **复盘**：踩过的坑与经验（这部分最值钱）

## 案例一：个人效率 —— 把每周报告从 3 小时压到 40 分钟

### 背景

某运营每周要交一份周报：汇总本周数据、说明异常、写下周计划。
痛点是**数据散在 4 个地方**（后台、表格、群聊记录、自己的笔记），
光"找齐材料"就要 1 小时，写又是 2 小时。

### 方案

把流程拆成三步，**材料收集仍然人工，AI 只负责整理与成文**：

**第一步（人工，20 分钟）**：把 4 处的数据和关键聊天记录复制进一个文本文档，
不做任何格式整理——**这一步千万别边复制边排版，那是最大的时间黑洞**。

**第二步（AI，5 分钟）**：用固定 Prompt 处理：

```
你是一位资深运营。以下是我本周的原始材料（数据、记录、备注混在一起）。

请完成：
1. 先列出你从材料里能确认的事实（只列有依据的，不要推测）
2. 指出数据中异常的地方，并说明"异常"的判断依据
3. 按「本周进展 / 异常与原因 / 下周计划」三段输出周报，每段不超过 150 字
4. 完成后自查：有没有出现材料里没有的数字？有就删掉

要求：语气平实，不要写"赋能""抓手"这类词。
---材料---
[粘贴原始材料]
```

**第三步（人工，15 分钟）**：核对数字、补充只有自己知道的背景、调整下周计划。

### 成效

| 环节 | 原耗时 | 新耗时 |
|------|-------|-------|
| 找齐材料 | 60 分钟 | 20 分钟（不做排版） |
| 整理成文 | 120 分钟 | 5 分钟 |
| 核对与补充 | — | 15 分钟 |
| **合计** | **180 分钟** | **40 分钟** |

### 复盘

- **最有效的一步不是"让 AI 写"，而是"取消边复制边排版"**——省下的 40 分钟里有一半来自这里
- Prompt 里"只列有依据的事实"这一句是关键：加上之前，AI 经常编造趋势；加上之后基本杜绝
- 第 4 条自查要求必须写，**它会拦掉"看起来很合理但材料里没有"的数字**
- 仍然保留 15 分钟人工核对：**周报是要对外负责的，不能全自动**

## 案例二：团队协作 —— 让会议纪要真正被用起来

### 背景

某 8 人团队每周开 3 场会，每场都有纪要，但**纪要写完就没人再看**。
调查后发现原因很直接：纪要太长、重点埋在中间、待办事项没有责任人。

### 方案

不是"用 AI 记纪要"，而是**改变纪要的结构**——让它变成"待办清单"而非"会议流水"。

**流程**：会议录音 → 转写工具出文字 → 用固定 Prompt 提炼 → 10 分钟内发到群里。

```
以下是本次会议的文字记录。请输出一份「可执行的会议纪要」，严格按下面的结构：

1. 决策事项（不超过 5 条，每条一句话，只写已经定下来的）
2. 待办清单（表格三列：事项 / 责任人 / 截止时间。责任人必须从记录里能确认，
   确认不了就写"待定"，不要猜）
3. 未决问题（不超过 3 条，写清卡在哪）
4. 不需要记录的寒暄与重复讨论，直接跳过

要求：
- 全文不超过 400 字
- 如果记录里没有任何明确决策，就只输出"本次会议无明确决策"和待办清单
---记录---
[粘贴转写文字]
```

### 成效

- 纪要长度从平均 1500 字降到 **300 字以内**
- 待办清单带责任人和截止时间后，**会上定的事有人跟了**——这是最大的变化
- 发到群里的纪要开始有人回复"这条我来"，说明**真的被读了**

### 复盘

- **"全文不超过 400 字"这个约束是成败关键**。去掉它，AI 会写出一份很全面但没人看的纪要
- "责任人确认不了就写待定"这一句很重要：早期版本 AI 会猜人名，出现过派错活的情况
- 转写质量决定上限：**会议本身说得含糊，纪要不可能清楚**。后来顺带改了开会习惯——结论要当场说清
- 涉及敏感讨论的会议不录音，这条边界要提前和团队说清楚

## 案例三：行业工作流 —— 客服工单的自动分类与初稿回复

### 背景

客服团队每天数百条工单，人工先判断类型（退款/物流/质量问题/咨询）再分派，
高峰期排队严重，且**同类问题重复写回复**。

### 方案

分两层做，**第一层只分类，第二层才生成回复**：

**第一层：分类（自动化）**
```
判断下面这条工单属于哪一类，只输出类别名，不要解释：
可选类别：退款 / 物流 / 质量问题 / 使用咨询 / 其他
如果同时涉及多类，输出最主要的一类。
---工单---
[工单内容]
```

只输出类别名，便于程序直接读取并路由。

**第二层：生成回复初稿（人工触发）**
```
你是客服主管。根据工单和对应的知识库条目，写一封回复。

要求：
1. 先共情一句，再给解决方案，不要上来就讲规则
2. 只使用知识库里提供的信息，知识库没有的内容不要编
3. 需要用户提供更多信息时，明确列出要哪几项
4. 结尾给出下一步时间点

---工单---
[工单内容]
---知识库条目---
[对应条目]
```

### 成效

- 分类环节从人工 30 秒/条降到**自动完成**，高峰期不再积压排队
- 回复从"从零写"变成"改初稿"，**同类问题处理时间明显下降**
- 意外收获：分类数据积累后，能看出哪类问题最多，反过来推动了产品改进

### 复盘

- **分类和生成必须分开**。早期想一步到位，结果分类错了整条回复都错，且很难排查
- 第二类 Prompt 里"只使用知识库提供的信息"是硬约束：**客服回复里编造政策是事故级问题**
- 自动化后必须有抽检：每天人工抽 20 条看分类是否准确，否则错误会静默积累
- 涉及用户个人信息的工单要先脱敏再交给外部模型——这条是上线的**前置条件**，不是可选项

## 通用复盘：三个案例的共同经验

| 经验 | 说明 |
|------|------|
| **先拆流程，再谈 AI** | 三个案例最大的收益都来自"重新设计流程"，AI 只是让新流程跑得动 |
| **约束比描述重要** | "不超过 400 字""只列有依据的事实""只输出类别名"——真正起作用的都是这类硬约束 |
| **保留人工核对环节** | 凡是要对外负责的产出，都留了人工确认步骤；省的是"写"的时间，不是"负责"的环节 |
| **边界先立，再上量** | 敏感信息脱敏、会议不录音、权限收紧——都是上线前定好的 |
| **抽检不能省** | 自动化会静默积累错误，定期抽检是唯一能发现的方式 |
