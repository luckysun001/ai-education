## 📅 程序员每日 AI 工作流

### 写代码之前：先让 AI 帮你搭架子

```
我要写一个 [什么功能，比如：Python 写一个解析 Excel 的工具函数

输入是：Excel 文件路径
输出是：解析后的结构化数据，包含 xxx 字段

请帮我：
1. 先设计一下这个函数的接口，参数怎么设计？返回值是什么格式？
2. 应该用什么库？有没有什么最佳实践？
3. 可能会有什么坑？文件格式不对？数据类型不对？大文件？
4. 给我一个完整的实现，要有注释，要有错误处理
5. 再给我 3-5 个使用例子
```

---

### 看不懂代码的时候：让 AI 给你讲明白

```
这是一段我看不懂的代码：
[把代码粘贴进来，或者整个文件]

这段代码是做什么用的？我在 [什么上下文] 看到的。

请帮我解释一下：

1. 用最简单的话，这段代码到底在干什么？
2. 整体的执行流程是什么？
3. 输入是什么？输出是什么？
4. 核心的数据结构是什么？
5. 这里面有没有什么坑？有没有写得不好的地方？
6. 哪些地方可能有 Bug？
7. 如果我要改某个地方，应该改哪里？会不会有什么副作用？
8. 给我画个简单的流程图或者时序图
```

---

### Debug 的时候：让 AI 帮你找问题

```
我遇到了一个 Bug：
现象是：[描述 Bug 现象，报错信息，堆栈]
相关的代码是：[粘贴相关代码]
我已经试过：[你已经做过哪些尝试，没用]

请帮我分析这个 Bug：

1. 最可能的原因是什么？按可能性排序，至少 5 个
2. 每个原因应该怎么排查？一步步告诉我排查步骤
3. 怎么验证是不是这个原因？
4. 找到之后怎么修复？
5. 有没有什么临时的 workaround？
6. 以后怎么防止以后再出现类似的 Bug？
7. 如果这个也不对，还有什么可能？给我一个排查思路
```

---

### Code Review 的时候：让 AI 先帮你看一遍

```
这是一个 PR 的代码：
[粘贴 PR 代码，或者给 Git diff]

请帮我做 Code Review：

1. 这个代码整体写得怎么样？1-10 分打个分
2. 哪些地方写得好？值得学习的地方？
3. 有没有明显的 Bug？哪里可能出问题？
4. 哪些地方可能有性能问题？
5. 哪些地方有安全漏洞？
6. 哪些地方写得不好，可以优化？
7. 有没有代码风格和我们的规范吗？有没有不符合？
8. 哪些地方缺少错误处理？边界情况没考虑？
9. 给我具体的修改建议，越具体越好
10. 按严重程度分类：必须改、建议改、可以不改
```

---

### 写单测的时候：让 AI 帮你写

```
这是我写的一个函数/类：
[粘贴代码]

请帮我写单元测试，用 [pytest / jest / junit 等测试框架]

1. 正常情况的测试用例
2. 边界情况的测试用例
3. 异常情况的测试用例
4. 各种错误输入的测试用例
5. 测试覆盖率要尽量高
6. 每个测试用例要写清楚测的是什么场景
7. 有没有什么不容易测到的地方，帮我指出来
```

---

### 重构代码之前：让 AI 帮你出方案

```
这段代码写得太烂了，我想重构一下：
[粘贴烂代码]

问题是：[说说你觉得哪里烂，想改成什么样]

请帮我：

1. 先分析一下这段代码现在有什么问题？
   - 可读性？性能？可维护性？扩展性？
2. 可以怎么重构？给我 2-3 个不同的方案
3. 每个方案的优缺点是什么？
4. 你推荐哪个方案？为什么？
5. 重构的步骤是什么？一步步来，不要一步到位改崩了
6. 每一步改完怎么验证有没有改坏？
7. 重构过程中最容易出什么问题？怎么避免？
8. 给我重构后的代码是什么样的？
```

## 🧠 核心场景 Prompt 模板

### 场景 1：学习新技术和新框架

```
我要学习 [某个技术/框架，比如 React 18、Rust、Go 等]，
我之前的技术栈是 [你会什么，比如 JavaScript、Python 等]。

请帮我设计一个学习路径：

1. 这个技术和我之前会的比，有什么不一样的地方？
   - 核心思想是什么？
   - 设计理念是什么？
   - 哪些地方是我可能会不适应的？

2. 最重要的核心概念有哪些？前 10 个，按重要性排序
   - 每个概念用最简单的话解释一下
   - 和我已知的什么东西可以类比？

3. 最常见的坑有哪些？
   - 新手最容易犯什么错误？
   - 哪些是反直觉的？
   - 哪些是网上教程一般不会告诉你？

4. 学习顺序是什么？
   - 第一天学什么？
   - 第一周学什么？
   - 第一个月要达到什么水平？

5. 给我推荐学习建议：
   - 必看的文档、教程
   - 必做的练习项目，从简单到难
   - 怎么判断自己学会了？

6. 我现在要写一个 [某个小项目]，用这个技术，
   给我一个项目结构建议，最佳实践
```

---

### 场景 2：写技术方案和设计文档

```
我要做一个 [什么项目/功能] 的技术方案，
需求是：[描述需求和目标]
约束条件是：[时间、资源、技术栈限制等]

请帮我写技术方案：

1. 有哪几种技术方案？至少 3 种
2. 每个方案的优缺点对比，列个表格
3. 你推荐哪个方案？为什么？
4. 整体架构是什么样的？画个架构图
5. 核心模块怎么划分？每个模块做什么？
6. 关键的技术难点是什么？怎么解决？
7. 可能会有什么风险？怎么应对？
8. 测试策略是什么？怎么测试？
9. 怎么上线？灰度？回滚方案？
10. 监控和告警怎么做？
11. 对性能、稳定性有什么影响？
12. 给我一个完整的技术方案大纲
```

---

### 场景 3：优化性能

```
这段代码有性能问题，太慢了：
[粘贴慢代码]

场景是：[什么情况下慢？数据量多大？慢到什么程度？

请帮我优化：

1. 先分析一下为什么慢？瓶颈在哪里？
2. 时间复杂度是多少？空间复杂度是多少？
3. 可以怎么优化？给我几种不同的优化思路
4. 每个优化思路能提升多少性能？ trade-off 是什么？
5. 优化后的代码是什么样的？
6. 怎么验证优化有没有效果？
7. 有没有什么副作用？会不会引入新的 Bug？
8. 还能不能再优化？极限在哪里？
```

---

### 场景 4：写 Shell 脚本和命令行工具

```
我要写一个脚本，做 [什么事情]，
用 [bash / python / powershell

请帮我写：

1. 完整的脚本实现
2. 参数怎么处理？
3. 错误处理和异常情况
4. 帮助信息和使用说明
5. 常见的坑和注意事项
```

---

### 场景 5：代码加注释和写文档

```
这是我写的代码：
[粘贴代码]

功能是：[简单说一下这段代码是做什么的]

请帮我：

1. 给每个函数写清晰的注释，说明：
   - 这个函数是做什么的
   - 参数是什么意思
   - 返回值是什么
   - 可能会抛出什么异常
   - 有什么副作用
2. 给复杂的逻辑块写行内注释
3. 写一个 README，说明这个模块怎么用
4. 写 3-5 个使用例子
```

## 真实案例

### 案例 1：用 AI 看祖传代码，半天搞懂半年的老项目

**背景**：某程序员接手了一个祖传项目，前任跑路了，代码没注释，文档没有，几十万行代码，完全看不懂。

**AI 用法**：
1. 把整个文件扔给 Claude 3
2. 让 AI 解释整体是干什么的，执行流程是什么
3. 看不懂的函数一个个问
4. 让 AI 给画流程图、时序图、架构图
5. 让 AI 给写注释

**效果**：原来可能要看一周才能搞懂的代码，半天就搞懂了，而且 AI 还帮他找到了好几个隐藏的 Bug。

---

### 案例 2：Debug 效率提升 10 倍，原来要 Debug 半天，现在 10 分钟

**背景**：某程序员遇到一个诡异的 Bug，复现概率低，堆栈信息少，查了半天找不到原因。

**AI 用法**：
1. 把现象、堆栈、相关代码、自己试过的方法都告诉 AI
2. AI 给了 5 个可能的原因，按可能性排序
3. 按 AI 给的排查步骤，一步步排查，第二个原因就找到了问题
4. AI 还给了修复方案，以及怎么防止以后再出现

**效果**：原来要花半天一天 Debug 的问题，10 分钟就找到原因并修复了。

## ⚠️ 避坑指南

### ❌ AI 写的代码，你一定要看懂！不要 Copy-Paste 就提交！

这是程序员用 AI 最容易犯，也是最危险的错误：

- AI 写的代码看起来好像是对的，跑起来好像也没问题
- 但你根本不知道里面藏了什么坑
- 上线了出问题，你连怎么回事都不知道，怎么修？

**重要原则：你提交的每一行代码，你都要为它负责。**
哪怕是 AI 写的，出了问题也是你的锅，不是 AI 的锅。

所以：
1. AI 写的每一行代码，你都要看懂
2. 一定要自己跑一遍，测一遍
3. 边界情况、异常情况一定要测
4. 不要把你看不懂的代码提交到代码库

---

### ❌ AI 会一本正经地胡说八道，用不存在的 API 和函数

这太常见了：
- AI 会告诉你用某个函数，结果这个函数根本不存在
- AI 会告诉你某个库有某个功能，结果根本没有
- AI 会给你一个看起来非常合理的代码，但是根本跑不起来

**重要原则：AI 说的任何 API、函数、参数，你都要去文档里确认一下。**

不要 AI 说什么你就信什么，一定要验证。

---

### ❌ 不要让 AI 帮你做核心架构决策！

AI 可以给你几个方案，可以帮你分析优缺点，
但是**用什么技术栈，选什么架构方案**，这些必须你自己拍板。

你是工程师，你要为这个技术决策负责，AI 不用负责。
AI 不知道你们团队的情况，不知道你们的技术债，不知道你们的历史包袱。

---

### ❌ 不要依赖 AI，失去自己写代码的能力！

不要变成离开 AI 就不会写代码的人：
- 基础的算法和数据结构还是要会
- 核心的业务逻辑还是要自己想清楚
- Debug 的能力还是要有，不能全靠 AI

AI 是放大器，不是替代器。
你自己越强，AI 帮你越多。
你自己越弱，AI 写的代码越烂，你越看不懂，越容易出问题。

---

### ❌ 绝对不要把公司的 proprietary 代码粘贴到公有 AI！

这个是红线！
- 公司的核心业务代码
- 没开源的代码
- 包含商业机密的代码

绝对不要粘贴到 GPT、Claude 这些公有服务里。

如果要用，用公司自己部署的私有化代码模型。
不然出了问题，轻则走人，重则吃官司。

## 📅 30 天学习计划

### 第一周：基础入门，把标配工具用起来
- 第 1-2 天：把 Copilot、Cursor 这些工具装上，写代码的时候开着，习惯它的存在
- 第 3 天：练用 AI 写简单的工具函数、脚本、重复代码
- 第 4 天：练用 AI 解释看不懂的代码
- 第 5 天：练用 AI 写单测
- 周末：总结一下，哪些场景用 AI 最顺手，哪些场景 AI 写得最好，哪些不行

### 第二周：进阶提升，解决实际问题
- 练用 AI Debug 和找 Bug
- 练用 AI 做 Code Review
- 练用 AI 做代码重构

### 第三周：高级技能，拉开和别人的差距
- 练用 AI 写技术方案和架构设计
- 练用 AI 学习新技术和新框架
- 练用 AI 做性能优化

### 第四周：形成自己的工作流
- 把 AI 融入你每天的编码工作流里
- 沉淀自己的 Prompt 库和使用习惯
- 知道什么情况该用 AI，什么情况不该用 AI，自己写更快

## 给程序员的心里话

很多程序员担心 AI 会抢自己的饭碗，
但实际上，现在的情况是：

**不会用 AI 的程序员，会被会用 AI 的程序员淘汰。**

同样一个需求，你写要 3 天，人家用 AI 辅助半天就写完了，
而且写得比你快，写得比你好，Bug 比你少，
你说老板会留下谁？

但是反过来，AI 也不会让差的程序员变成好程序员。
基础不牢，地动山摇。
你自己本身是个优秀的程序员，AI 能让你变成 3-5 倍效率的超级程序员。
你自己本身代码就写得烂，AI 只会帮你写出更多更烂的代码，还多了很多你看不懂的隐藏 Bug。

所以：
1. 好好打基础，这个永远不会过时
2. 拥抱 AI，把它变成你的超能力
3. 把时间从重复劳动中解放出来，花在更有价值的地方：架构设计、系统思考、解决真正难的问题
