## 📅 产品经理每日 AI 工作流

### 上班第一件事（10 分钟）

```
你是我的产品经理助理。
我今天的任务是：[列一下你今天要做的 3-5 件最重要的事]

请帮我：
1. 把这些事情按优先级排序，说明为什么
2. 每件事情大概需要多久，给我一个时间规划
3. 哪些事情可以先用 AI 做准备？分别怎么用？
```

---

### 写 PRD 之前（15 分钟）

先让 AI 帮你搭框架，不要从零开始写：

```
我要写一个关于 [功能/项目名称] 的 PRD。
这个功能的目标是：[简单说一下要解决什么问题，给谁用]
核心的用户场景是：[1. xxx 2. xxx 3. xxx]

请帮我搭一个 PRD 的框架：
1. 这个 PRD 应该包含哪些部分？
2. 每个部分应该写什么内容？
3. 哪些地方是最容易遗漏的？
4. 哪些地方需要特别想清楚？
5. 给我一个完整的目录和每个部分的写作要点
```

---

### 分析用户反馈（30 分钟，原来要 3 小时）

```
这是最近一周的用户反馈和评论，大概有几百条：
[把所有反馈粘贴进来，或者上传文件]

请帮我做全面的分析：

1. 整体情绪分析
   - 正面反馈占多少？负面反馈占多少？中性的占多少？
   - 用户整体满意吗？

2. 关键词和主题分类
   - 大家提到最多的 10 个问题/点是什么？
   - 按出现频率排序，每个问题给一些例子
   - 用饼图或者树状图的结构展示

3. 正面反馈总结
   - 用户最喜欢我们的什么地方？
   - 哪些点夸得最多？
   - 能不能提炼出 3-5 个核心好评点？

4. 负面反馈和吐槽总结（最重要）
   - 用户骂得最多的是什么问题？
   - 按严重程度排序
   - 每个问题给一些最典型的用户原话
   - 哪些问题是反复被提到的？

5. 功能建议和需求收集
   - 用户最希望我们加什么功能？
   - 按呼声排序
   - 哪些需求是类似的，可以合并？

6. 奇怪的、意外的、有趣的反馈
   - 有没有什么我们没想到的用户反馈？
   - 有没有用户的用法完全出乎我们的意料？

7. 优先级建议
   - 基于这些反馈，接下来最重要的 3 件事是什么？
   - 为什么？
```

---

### 竞品分析（1 小时，原来要 3-4 小时）

```
我要做 [某个产品/功能] 的竞品分析。
我分析的竞品是：A、B、C 这几个产品。

我已经收集到的信息是：
[把你知道的信息列出来]

请帮我：

1. 先搭一个竞品分析的框架
   - 应该从哪些维度对比？
   - 哪些维度是最重要的？
   - 给我一个对比表格的结构

2. 基于你对这几个产品的了解，先填一版
   - 每个产品的定位和特点
   - 每个产品的优点和缺点
   - 每个产品的核心功能对比
   - 用户群体有什么不一样？
   - 商业模式和盈利点有什么不一样？

3. 每个产品做得最好的地方是什么？
   - 哪些点值得我们学习？
   - 哪些是它们的护城河？我们很难抄的？

4. 每个产品做得最烂的地方是什么？
   - 哪些是我们的机会？
   - 哪些坑我们可以避免？

5. 差异化机会
   - 我们和它们相比，可以有什么不一样的地方？
   - 我们可以切哪个细分市场？
   - 有什么功能是它们肯定不会做，但是我们可以做的？

6. 给我们的建议
   - 基于这个竞品分析，我们接下来应该怎么做？
   - 哪些可以直接抄？
   - 哪些要做差异化？
   - 哪些坑绝对不要踩？
```

---

### 评审前准备（30 分钟）

```
我明天要做一个 [功能/项目] 的需求评审，
参会的有：研发、测试、设计、老板。
这个需求的核心内容是：[简单说一下]

请帮我准备评审材料：

1. 我应该怎么开场？怎么用 3 句话把这件事说清楚？
2. 大家可能会问哪些问题？至少列 15 个，按可能性排序
3. 每个问题我应该怎么回答？
4. 哪些问题可能会有争议？我应该怎么应对？
5. 研发可能会challenge什么？怎么说服他们？
6. 老板可能会关心什么？怎么提前准备好答案？
7. 我最担心被问到的问题是 [xxx]，帮我准备 3 个不同版本的回答
8. 最后我怎么收尾，怎么推动大家拍板和排期？
```

---

### 写数据分析报告（30 分钟）

```
这是我们最近上线的 [功能/项目] 的数据：
[把数据表格、关键指标列出来]

请帮我写一份数据分析报告：

1. 核心结论先写在最前面（3-5 条）
2. 这个功能/项目达到预期了吗？打几分？
3. 哪些指标好？哪些指标不好？为什么？
4. 数据里有没有什么异常的地方？值得注意的？
5. 有没有什么意外的发现？
6. 用户的行为和我们之前设想的一样吗？哪里不一样？
7. 接下来应该怎么做？
   - 哪些地方要优化？
   - 哪些方向要继续投入？
   - 哪些方向可以砍掉了？
8. 给我一个报告的大纲，分点写清楚
```

## 🧠 核心场景 Prompt 模板

### 场景 1：用户需求分析和判断

```
用户提了一个需求：[用户原话]
用户的背景是：[什么类型的用户，什么场景下提的]

请帮我分析这个需求：

1. 这个用户真正想要的是什么？（透过需求看本质）
   - 他说的是 A，但他真正想要的是不是 B？
   - 这个问题背后的根本原因是什么？

2. 这个需求有代表性吗？
   - 大概有多少用户会有同样的问题？
   - 是共性需求还是个性需求？
   - 是高频还是低频？

3. 如果我们不做，会怎么样？
   - 用户会走吗？
   - 会有很大的负面影响吗？
   - 还是其实没什么大不了的？

4. 如果我们要做，有哪几种解法？
   - 最简单的解法是什么？
   - 最完美的解法是什么？
   - 投入产出比最高的解法是什么？

5. 有没有什么替代方案？
   - 不做功能，有没有其他方式可以解决这个问题？
   - 运营手段？文案引导？用户教育？

6. 优先级建议
   - 这个需求应该排 P 几？为什么？
   - 什么时候做最合适？
```

---

### 场景 2：功能逻辑和流程梳理

```
我们要做一个功能：[简单描述功能]
核心流程是：[用户从进入到离开的完整路径]

请帮我梳理一下这个功能的逻辑和流程，帮我查漏补缺：

1. 主流程有没有问题？有没有遗漏的步骤？
2. 各种异常情况和边界情况
   - 用户没登录怎么办？
   - 数据加载失败怎么办？
   - 用户网络不好怎么办？
   - 用户操作到一半退出去了怎么办？
   - 用户权限不够怎么办？
   - ... 把你能想到的所有异常情况都列出来
   - 每种情况系统应该怎么处理？怎么提示用户？

3. 不同用户角色的体验
   - 新用户第一次用会怎么样？
   - 老用户习惯了旧功能会怎么样？
   - 不同权限的用户看到的有什么不一样？

4. 极端情况
   - 如果数据量特别大怎么办？
   - 如果同时有很多人操作怎么办？
   - 如果用户连续快速点击怎么办？

5. 和其他功能的关联和影响
   - 这个功能上线，会影响哪些已有的功能？
   - 哪些地方可能会有冲突？
   - 数据会不会不一致？

6. 我有没有漏掉什么重要的场景？
```

---

### 场景 3：生成测试用例

```
这是一个功能的需求描述：
[把 PRD 里的需求描述粘贴进来]

请帮我生成完整的测试用例：

1. 按测试类型分类：
   - 功能测试用例
   - 边界测试用例
   - 异常测试用例
   - 性能测试用例
   - 兼容性测试用例
   - 安全测试用例

2. 每个测试用例包含：
   - 用例 ID
   - 测试场景
   - 前置条件
   - 测试步骤
   - 预期结果
   - 优先级

3. 按优先级排序，P0 先列出来，就是发版之前必须测过的。

4. 哪些地方最容易出 Bug？重点标出来。

5. 有没有什么需求写得不清楚，测试没法测的？帮我指出来。
```

---

### 场景 4：写产品规划和 Roadmap

```
我们下个季度的 OKR 是：[列出来]
目前我们手上的需求池有：[列一下主要的需求和项目]

请帮我做下个季度的产品规划和 Roadmap：

1. 先帮我把这些需求分类和梳理
   - 哪些是为了达成 OKR 必须做的？
   - 哪些是用户一直喊的，不得不做的？
   - 哪些是技术债，必须还的？
   - 哪些是锦上添花，可做可不做的？

2. 优先级排序
   - 按重要程度排序，说明理由
   - 按紧急程度排序
   - 做一个四象限图

3. 时间规划和 Roadmap
   - 第一个月做什么？
   - 第二个月做什么？
   - 第三个月做什么？
   - 哪些可以并行？哪些有依赖关系？

4. 资源评估
   - 大概需要多少研发资源？
   - 哪些地方可能会成为瓶颈？
   - 哪些可以借别的团队的力？

5. 风险评估
   - 这么排，最大的风险是什么？
   - 哪些项目可能会延期？
   - 如果时间不够，应该先砍哪些？

6. 怎么和老板和团队说这个规划？给我一个讲稿大纲。
```

## 真实案例

### 案例 1：用 AI 分析 500 条用户反馈，30 分钟搞定

**背景**：某产品经理，版本上线后收了 500 多条用户反馈，一条条看要看好几个小时，还容易漏。

**AI 用法**：
1. 把所有反馈复制粘贴到 Claude 3
2. 用上面的用户反馈分析 Prompt
3. 3 分钟就得到了分类、关键词、情绪、TOP 问题
4. 自己再花 20 分钟看一下 AI 标出来的重点问题，验证一下

**效果**：原来一下午的工作，30 分钟搞定，而且分类和总结比自己一条条看还全面，还不会漏。

---

### 案例 2：PRD 写作效率提升 3 倍

**背景**：某产品经理写 PRD 总是要花很久，搭框架、想场景、写逻辑，还要担心漏了什么。

**AI 用法**：
1. 先把需求的核心目标和几个关键场景告诉 AI
2. 让 AI 先搭 PRD 框架，把每个部分要写什么都列出来
3. 自己填核心内容，填完让 AI 帮你梳理逻辑、查漏补缺
4. 让 AI 帮你想边界条件、异常场景，检查有没有遗漏
5. 最后让 AI 帮你调整排版和格式，变得更专业

**效果**：原来写一份完整的 PRD 要 2-3 天，现在半天就写完了，而且 AI 帮你想到了很多你自己没想到的异常场景和边界情况，需求写得更周全了。

## ⚠️ 避坑指南

### ❌ 不要让 AI 代替你做产品决策！

AI 可以帮你收集信息、整理信息、给你建议，
但是**用户是谁、用户要什么、产品应该往哪个方向走**，这些决策必须你自己做。

不要因为 AI 说应该这么做，你就真的这么做。
AI 没有产品感觉，不懂你的用户，不懂你的业务。

你是产品经理，你要为决策负责，AI 不用负责。

---

### ❌ 用户反馈分析完，一定要自己抽样验证！

AI 总结用户反馈会出错：
- 有时候会把完全相反的意思理解反
- 有时候会漏掉重要的信息
- 有时候会编造不存在的内容

所以 AI 分析完之后，你一定要：
1. 每个分类抽 5-10 条原文看看对不对
2. 特别关注 AI 标出来的「严重问题」，看是不是真的严重
3. 太离谱的结论，一定要回去看原文

不要 AI 说什么你就信什么。

---

### ❌ 不要直接把 AI 写的 PRD 发给研发！

AI 写的 PRD 大概率：
- 太泛，不够具体
- 很多细节不清楚
- 有些逻辑完全是错的
- 不符合你们团队的写文档习惯

你必须自己：
1. 把核心内容改对，改成符合你们业务的
2. 把逻辑理清楚，不要有矛盾
3. 加上你们团队特有的规范和格式
4. 把例子和细节补上，让研发能看懂

记住，AI 是帮你打草稿的，不是帮你写终稿的。

---

### ❌ 不要把内部需求和商业机密随便喂给公有 AI！

- 还没上线的功能规划
- 公司的 OKR 和商业数据
- 用户的敏感信息和数据
- 和竞品有关的敏感分析

这些东西，最好不要随便粘贴到公有 AI 服务里。
如果要用，用你们公司自己部署的私有化模型。

## 📅 30 天学习计划

### 第一周：基础入门
- 第 1 天：把用户反馈分析这个技能练熟，以后每次有反馈都先用 AI 分析
- 第 2-3 天：练 PRD 框架搭建，以后写文档先让 AI 搭框架
- 第 4-5 天：练竞品分析，用 AI 帮你快速出框架和思路
- 周末：总结一下，把你常用的 3-5 个 Prompt 存下来

### 第二周：进阶提升
- 练功能逻辑梳理和查漏补缺
- 练数据分析报告
- 练评审前准备

### 第三周：场景拓展
- 练测试用例生成
- 练产品规划和 Roadmap
- 练用户需求分析和判断

### 第四周：形成自己的工作流
- 把 AI 融入你每天的工作流程里
- 沉淀自己的 Prompt 库和模板
- 教团队里的其他产品经理也用起来
